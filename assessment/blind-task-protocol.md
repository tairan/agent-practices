# Blind Task 实施协议

## 目的

Blind task 用于判断学习者能否把已知机制迁移到未知输入、故障、攻击或约束。公开 fixture、自己编写的失败案例和重复演示不能单独证明 L3 或 L4。

## 角色隔离

- **设计者**：准备任务、隐藏样本、评分规则和安全停止条件，不参与被测实现。
- **执行者**：只获得问题陈述、允许资源、时间和风险边界。
- **复核者**：核对原始运行记录、评分和是否发生信息泄露；可以与设计者是同一人，但不得是执行者。

评审记录必须写明角色、任务版本、开始和结束时间、允许的提示、是否发生泄题以及异常中止原因。

## 样本隔离

1. 开发集可以公开并用于调试。
2. 验收集输入可以公开或半公开，但预期结果和评分器不得被实现读取。
3. 盲测集在执行前不得进入 prompt、代码、fixture、文档、提交历史或学习者可访问日志。
4. 任务运行后才公开的样本必须记录公开时间和版本。
5. 发现泄漏后该轮结果无效，必须更换样本或生成 seed。

## 单人自学替代方案

单人环境无法对已阅读的固定 fixture 建立真正盲测。可以使用：

- 独立进程按未提前公开的随机 seed 生成属性测试案例。
- 由 CI、教师或独立 Agent 保管的验收包，只返回最小失败信息。
- 延迟发布或加密保存的任务包，由第三方在验收时释放。
- 从公开规则动态组合故障，但在运行前隐藏具体组合和参数。

独立 Agent 可以担任设计者或复核者，但必须使用独立 session，不能继承执行过程中的隐藏答案、草稿结论或私有评测数据。其提示、输入范围和输出必须随 evidence 保存。

## 任务类型

- 未知输入：边界值、歧义、无证据请求和格式变体。
- 未知故障：超时、限流、崩溃、重复投递、部分写入和状态损坏。
- 未知攻击：prompt injection、跨 tenant、错误 audience、审批替换和数据外传。
- 未知约束：成本上限、延迟目标、兼容版本或权限缩减。

## 评分与停止

- 任务开始前固定通过条件、时间、允许工具和评分方式。
- 安全不变量优先于任务成功率；触发不可逆风险时必须停止。
- 评分同时覆盖最终结果、诊断过程、止损、恢复和决策质量。
- 只给出结论而无原始记录，或只保留成功运行，不得通过。
- 复核者必须说明 evidence 是否充分、是否存在污染及残留不确定性。
